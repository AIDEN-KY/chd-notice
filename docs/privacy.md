# 通知与摘要外发策略

默认流程按维护者要求：正文转成纯文本后交给 DeepSeek，摘要优先保留时间、地点、QQ群号、
联系方式与行动要求；邮件标题、摘要、详情链接及附件的排版不变。
一般以 50–80 字为目标，关键信息较多时允许超过，不通过硬截断丢弃联系方式。
提示词要求并不保证模型输出完全正确，正式验收需人工核对真实摘要。

`AI_SUMMARY_ENABLED=false` 时不构造 HTTP 客户端、不读取 API Key、不调用 DeepSeek，
摘要降级为通知标题。`AI_EXCLUDED_KEYWORDS` 使用 `||` 分隔，默认拦截“内部资料”“禁止转发”
“保密”“不得外传”；匹配范围为完整标题与可见正文（在正文截断之前检查）。
配置值错误明确报错。日志不记录通知正文、匹配标题、密钥或 HTTP 异常原文。

关键词只是兜底，不是完整敏感信息分类器。该开关只控制新的 AI 请求：历史缓存摘要不会自动
删除；关闭 AI 不等于停发邮件。命中关键词时降级为标题，也不等于整个通知和附件已经被禁止
分发。正式多人投递仍关闭，须在内容分发边界及敏感通知/附件的整条投递策略确认后再开放。

目前没有取得学校对全部通知的转发或第三方 AI 处理授权依据。不要将网络可访问、订阅同意
或程序正常运行当作这项授权。维护者需确认获准的内容范围；不确定内容默认不进入正式群发。
不要公开 auth.json、受限附件、订阅者邮箱或包含校内内容的 SQLite 备份。
