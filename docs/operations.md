# Windows 本地运维与恢复

## 安全边界

只维护单机 SQLite。备份含收件人、通知、摘要及投递审计，选用本地非同步目录，
不要放到公开仓库、网盘自动同步目录或分享给其他同学。不自动上传备份。
Windows 上为备份目录配置仅管理员/运行账户可访问的 NTFS 权限；chmod 不能替代 Windows ACL。
auth.json 和 .env 单独保护，数据库备份不包含它们；丢失会话后手动登录，不保存学校密码。

## 上线前检查

在项目根目录运行，虚拟环境不需要先激活：

```powershell
.\.venv\Scripts\python.exe main.py doctor
.\.venv\Scripts\python.exe main.py preview
```

doctor 只检查，不创建数据库/目录/日志、不升级旧库、不联网。退出码 0/1 表示检查通过/失败。
目录未创建时只报告，不通过写文件来探测权限。目录存在也不承诺具有有效写权限。
配置范围错误可能在启动加载时直接失败，错误信息只包含配置名，不包含填写值。
doctor 无法证明 CAS 尚有效、SMTP 可达或邮件已经进入收件箱。
可选 UNSUBSCRIBE_URL 只接受无嵌入凭据、无控制字符的有效 HTTPS URL；
配置错误时 doctor 失败且不打印值。未配置保留人工 mailto 通道。
通过 URL 格式校验不代表页面已部署或退订已经生效，仍须人工验收。

需要明确初始化或增量迁移时，先备份已有库，再运行：

```powershell
.\.venv\Scripts\python.exe main.py init-db
```

该命令不抓取、不发邮件。旧 schema 0 原地升级至 1，重复执行保留所有记录；
未来版本拒绝降级。首次尚无数据库无需备份。升级前必须停任务，迁移时还有任务锁保护。

## 备份及离线恢复演练

目标父目录必须已存在，目标文件必须不存在。以下命令使用项目目录作示例，
实际部署可用已配置权限的本地备份目录，每次取不同文件名：

```powershell
.\.venv\Scripts\python.exe main.py backup --output "backup-2026-10-11.db"
.\.venv\Scripts\python.exe main.py restore --input "backup-2026-10-11.db" --output "rehearsal-2026-10-11.db"
```

不要重复使用示例文件名覆盖既有备份。backup 使用 SQLite 在线备份 API，
而非直接复制 .db；因此包含已提交的 WAL 数据。复制后做 quick_check、schema 及必要表检查，
先生成临时文件，再以拒绝覆盖的原子硬链接发布到新目标；只适用于支持硬链接的本地文件系统
（例如 NTFS），不支持时安全失败，不自动放宽为覆盖写入。失败清理本次临时文件。
备份循环约 60 秒预算，不承诺系统文件 I/O 严格实时。

restore 使用同一验证/复制流程，只生成新的演练库，拒绝以当前运行数据库为目标。
不修改源库或补发邮件。schema 0 可作旧库快照保存，但 doctor 可能要求先显式升级；
损坏、不兼容的新版本或不认识的数据库拒绝恢复。JSON status=ok 代表生成并验证成功，
不代表已经切换正式系统。自动测试已核验全部表及 accepted/unknown 记录一致。

真正回切前停 scheduler/任务计划，保留当前数据库及 WAL/SHM 和投递日志，核对备份时间后
实际发送过哪些邮件。旧备份可能没有这些投递事实，未经人工核对直接回切可能重复发信。
本版本不提供覆盖正式库的一键恢复。实际回切方案需另行确认，不能仅凭演练成功直接群发。

## 定时运行二选一

方案 A：手动常驻 `main.py scheduler`。窗口必须保持运行，电脑不能睡眠/关机。
关机后进程消失；翌日仅开机不会自动启动 scheduler，需手动启动或另配启动机制。
无持久化调度存储，重启不会自动补上前一天错过的 21:00。

方案 B：Windows 任务计划，每天 21:00 执行项目的 run_daily.bat（内部 send-now）。
不再同时运行 scheduler；任务设置“如果任务已运行，则不启动新实例”。
设置起始目录为项目根目录，运行账户必须能访问 E 盘、虚拟环境、.env、auth.json。
选用后台运行账户时须自行确认其网络、登录会话文件及权限与手动运行一致。

如需错过时间后补跑，可在 Windows 设置“错过计划开始时间后尽快运行”；
如需睡眠唤醒，设置“唤醒计算机运行此任务”，但受硬件/系统电源设置限制。
关机时不能执行；这些选项需用户实际验证，不能承诺每天必达。
批处理不依赖激活环境，目录有空格也可运行；Python 环境缺失返回 2，保留主程序退出码。

退出码说明：send-now 正常 0，降级/预算耗尽 3；任务锁冲突 2，未处理错误通常 1。
任务计划显示非零时先看日志及 doctor；不要用循环立即重试 unknown 投递。
管理员确认 unknown 时填写核对原因，只有明确拒收者按固定快照有限补发。
系统管理员告警有冷却期；发送成功也只代表 SMTP 接受，不代表收件箱收件。

## 部署和 CI

部署完整仓库，保留 tests/manual_email（send-test 所需工具），不要只复制业务 .py。
依赖使用 requirements.txt、requirements-dev.txt；安装 Chromium 并保持项目专属浏览器目录。
不要在 CI 放真实 CAS、DeepSeek、QQ 凭证；CI 使用假服务和临时库。
CI 配置为 Ubuntu/Windows × Python 3.11/3.13，检查 Ruff lint、format、pytest、编译。
配置已增加矩阵不代表远端 CI 已通过，需核验对应提交的运行结果。
运行时可用 `python main.py --version` 查看软件版本，数据库版本另用 PRAGMA user_version。
